# WBS・マスタースケジュール画面（#wbs）設計 v1（2026-11-24）

依頼：Hiro「タスクがぐちゃぐちゃ。カテゴリ分けをきれいにして、NotionとTCCの両方で抜け漏れなく見える化。WBS・マスタースケジュールを作って」（2026-11-24 音声）

## 1. 方針
- **正本はNotionのマスタータスクDB**（`collection://0f570283-d51e-4797-912a-57b54d72e381`）。TCCは読むだけ。新しいDB・JSONの正本は作らない。
- Notion側の「🗂 WBS・マスタースケジュール」ページと同じ構造を、TCCでスマホ1画面に収まる形で出す。
- 個人名・相手先名・金額は公開の静的JSONに出さない（このリポジトリは public）。`/api/private-tasks` と同じオーナー認証の裏で読む。

## 2. 画面構成（上から順）
1. **今日Hiroがやること**（最大5行・期限順）：担当AI＝👤 Hiro の行。1行＝期限｜何を｜所要。
2. **柱ごとのカード**（横スクロールではなく縦積み）
   - 柱1 物件を買う（仕入れ）／柱2 仲介・紹介（手数料）／柱3 資金調達／柱4 営業の型・仕組み／柱5 守り（期限つき）
   - カードの頭に「進行中 n／止まり n／今週期限 n」の3つの数字。止まり（ブロック中・期限超過・7日以上更新なし）は赤。
   - 中に中項目→タスクの2段。1行＝状態アイコン｜タスク名｜担当（Hiro/Claude/Muse/Codex/Antigravity）｜期限｜次の一手（1行で切る）。
   - 行をタップするとNotionの行ページを開く（詳細はNotion本文が正本）。
3. **マスタースケジュール（4週間のバー）**：期限・期日があるタスクだけ、週単位のバー。今日の線を引く。土曜は網掛け（送信しない日）。
4. **振り返り未実施の面談**：カレンダーにあって振り返りログがない面談を1行ずつ（例：11/24 360室大家、トーセイ阪口様）。

## 3. データの対応
| 画面 | Notion列 |
|---|---|
| 柱 | 新しい選択列は作らず `WBSサマリー` の先頭「柱n｜」で判定（無ければ `統合カテゴリ` で振り分け） |
| 中項目 | `上位` リレーション（戦術行）。無ければ `WBSサマリー` の2番目 |
| 状態 | `ステータス` ＋ `実行状況`。止まり＝⏸ブロック中 or 期限超過 or 最終更新7日超 |
| 担当 | `担当AI`（無ければ `担当`） |
| 期限 | `期限` → 無ければ `期日` |
| 次の一手 | `次の一手` |
| 除外 | `完了`=YES、`アーカイブ`=YES、`優先区分`=⑤保留（保留は最下部に件数だけ） |

## 4. API
- `GET /api/private-wbs`：`functions/_lib/notion.ts` の既存クライアントで上記列だけをSQL1回（またはview）で取得し、柱→中項目→タスクに整形。KV5分キャッシュ。オーナー認証必須（未設定は503）。
- `?refresh=1` はオーナーだけ。

## 5. 受け入れ条件
- iPhone幅（390px）で横スクロールなし。柱カードは折りたたみ可。
- Notionで行を変えると5分以内に画面へ反映（refreshで即時）。
- 公開の `/data/*.json` に相手先名・金額が出ていないことをテストで確認。
- `npm run lint / npm test / npm run build` が通り、本番で `#wbs` を開いて表示を確認するまで「完了」としない。
